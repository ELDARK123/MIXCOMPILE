# Data, Paper, and Code Correspondence Audit

## Corresponding items

The formal optimized evaluation is internally consistent across data, paper,
and implementation interfaces:

- llama.cpp arithmetic means in `paper_extracted/llama_arithmetic_means.csv`
  reproduce the paper's 31.994/11.276, 37.012/12.019, and 32.329/11.119 values.
- OpenSSL arithmetic means and optimized/LLVM ranges reproduce the paper tables
  and figure inputs.
- radiff2 correctness-eligible medians reproduce 0.562, 0.590, and 0.314 for
  optimized against GCC, LLVM, and OLLVM-full.
- Ghidra per-program-median ratios reproduce the reported optimized 8.109x.
- optimized correctness is 31/31.
- the formal compiler manifests use `-mix-profile=optimized`, threshold 0.0 by
  default, seed 1, and the optimized weight JSON.
- the three formal optimized weight files have the same SHA-256,
  `8b23633cef3c2fbdae7e14d8d774e5d7f684ef7aa487aa6dcd5da8c9db340cf4`,
  matching the formal configuration.
- the current code defines optimized global weights as
  `<1.10, 1.05, 0.90, 0.25, 0.95>` and BCF gates of 2000 instructions and 500
  expected modified basic blocks, matching the formal experiment configuration
  and paper method section.

The parameter summary values also numerically reproduce the current paper:

- sensitivity: default plus ten perturbations, all 27/27;
- ablation: ratios derived against the original baseline reproduce all reported
  size, execution, and compilation ratios;
- random perturbation: 30/30 configurations pass, with runtime median 1.668848 s,
  similarity median 0.789839, and IQR 0.018387;
- transfer: Stanford 11/11, 15 binaries, 267 annotations, similarity 0.690,
  execution 0.072818 s, and compilation 1.8893 s.

## Non-corresponding items

### Calibration profile

The parameter source records `-mix-profile=balanced`, while the paper labels the
same unchanged numbers as optimized-profile results. Current code gives balanced
and optimized different global vectors, so the label is not interchangeable.

### Source revision

The parameter experiment's recorded PassDecider source hash differs from the
current repository file. The summary tables are historical results rather than
measurements of the exact current source tree.

### Per-pass calibration table

`calibration_partial/tables/table_pass_metric_baseline.csv` does not fully
reproduce the paper's per-pass table. FLA size, IBR execution time, and IGV
execution time conflict with the TeX values, and the CSV has no compile-time
ratio column. Other experiment folders show that the paper's final column values
are Ghidra ratios, not true compilation-time ratios. The paper should relabel
that column or replace it with compile ratios derived from a single pass-only
campaign.

### Raw sensitivity and ablation data

The summary tables exist, but the currently available raw files omit the ten
sensitivity and eight ablation configurations. These sections are numerically
traceable to summaries but not independently auditable per program.

## Recommended paper corrections

1. Describe sensitivity, ablation, random perturbation, and transfer as the
   historical balanced/default calibration campaign, or rerun them with the
   formal optimized profile and frozen optimized weight file.
2. Correct the per-pass table's last column and use one coherent pass-only data
   source for every column.
3. State the exact source/compiler hashes for calibration and formal evaluation
   separately; do not imply that every table was generated by the current
   working-tree source.
4. Restore the missing sensitivity and ablation raw rows before submission if
   full artifact reproducibility is claimed.
